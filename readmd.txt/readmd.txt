### After Creating `df_clean`

We first created an independent copy of the original dataset so that we could safely perform cleaning and analysis without accidentally modifying the original `df`.

```python
df_clean = df.copy()
```

After that, we started investigating the dataset **step by step** instead of directly deleting missing or suspicious values.

#### 1. Checked `CustomerID` missing values

We found:

* Missing `CustomerID` = **132,603 rows**
* Missing percentage = **24.58%**

We calculated the percentage using:

```python
df_clean["CustomerID"].isna().mean() * 100
```

Here, `isna()` returns `True` for missing values and `False` for non-missing values. Python treats `True` as `1` and `False` as `0`, so taking the mean gives the proportion of missing values.

#### 2. Checked the value of missing-CustomerID transactions

We calculated:

```python
Quantity × UnitPrice
```

for rows where `CustomerID` was missing.

Total transaction value:

**£1,469,806.24**

This showed that missing `CustomerID` rows contain a significant amount of transaction data, so we should not simply delete them.

#### 3. Checked negative quantities

Among the rows with missing `CustomerID`, only **383 rows** had negative quantities.

This was a very small portion of the missing-CustomerID records.

#### 4. Investigated those negative-quantity records

Some common descriptions were:

* `Manual`
* `SAMPLES`
* `AMAZON FEE`
* `POSTAGE`
* `Bank Charges`

This showed that negative quantity does not always mean a normal customer return. Some records appear to be operational or accounting-related.

#### 5. Checked which countries had missing CustomerIDs

Most missing `CustomerID` records were from the **United Kingdom**:

* UK = **131,125**
* Total missing = **132,603**

So approximately **98.9%** of the missing-CustomerID rows were from the UK.

#### 6. Checked unique invoices

Although there were **132,603 rows** with missing CustomerID, they belonged to only **1,610 unique invoices**.

This reminded us that:

> **Rows are not the same as orders/invoices.**

One invoice can contain many product lines.

For example, invoice `573585` alone contained **1,114 rows**.

#### 7. Checked whether CustomerID was missing for the whole invoice

We found:

* **1,610 invoices** → CustomerID missing for every row
* **22,186 invoices** → CustomerID was not missing for every row

This helped us understand that missing CustomerID is concentrated in specific invoices rather than being randomly distributed across individual rows.

### Final Decision

We decided **not to delete the missing `CustomerID` rows**.

The reason is that these transactions contain valuable sales information and are useful for analyses such as:

* Product analysis
* Sales analysis
* Country analysis
* Revenue/transaction analysis

However, for **customer-level analysis** such as RFM or customer segmentation, rows without `CustomerID` will need to be handled separately.

**Important:** We are not assuming that every missing `CustomerID` record is a valid customer sale. We investigated the pattern first and made the cleaning decision based on the evidence.
